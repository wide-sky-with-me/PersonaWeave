# 文档分三层：规则、事实、决策，并用测试守住

状态：有效
日期：2026-10-04

## 背景

`AGENTS.md` 长到 1.5 万字，规则、实现细节和历史叙述混在一起，Agent 很难遵守；`docs/` 里有按日期堆叠的补丁章节、一次性审计报告和评测流水账（单篇最长 5.7 万字）；`README.md`/`DESIGN.md` 尾部按修复时间追加段落。参考的做法是 DeepSeek Harness 项目：根 `AGENTS.md` 只放短规则加链接，`docs/` 只写当前事实，`.agents/notes/` 记录“为什么”和被否定的方案，并用 CI 限制文档长度、禁止历史变迁词。

## 决策

- 三层分工与规则写进 [documentation-governance.md](../../../docs/documentation-governance.md)，`AGENTS.md` 只留一行规则加链接。
- 用 `tests/test_documentation_governance.py` 机械守住：字符上限、事实文档不含历史变迁词、无孤儿文档、笔记结构完整且可从文档找到、无全局索引。
- 大文档按职责拆分而不是硬砍：精修拆成契约、会话接口与存储、工作台与恢复三份，工程保存与恢复从任务历史里独立，历史质量档案边界并入 `delivery-quality.md`。
- 已有设计原则类内容（如任务历史的“工程原则”）迁成决策笔记。

## 被放弃的方案

- **继续往 `AGENTS.md` 追加细则**：已证明会膨胀并降低遵守率。
- **建全局 `INDEX.md` 索引笔记**：多分支并行时必然合并冲突；改为要求文档链接到各自的笔记，并用测试检查可发现性。
- **把决策写进 `CHANGELOG.md`**：它按日期追加，回答“什么时候改了什么”，不适合按主题检索“为什么”。
- **各目录放子级 `AGENTS.md`**：工具不保证加载嵌套规则文件，关键规则可能读不到；规则留在根文件，细节放文档。
- **一刀切 12,000 字上限并立即砍到合规**：会丢掉核心契约的语义；改为默认上限加存量“只降不升”的棘轮，超限文档逐步拆分。
- **用宽泛词表禁历史词**：“旧版本”“used to protect”等是功能性用语，误报会让规则被忽略；词表只收明确的变迁叙述（此前、不再、previously 等）。

## 影响与验证

规则见 [AGENTS.md](../../../AGENTS.md) 文档规则一节；检查 `tests/test_documentation_governance.py`。精修文档按职责拆成契约、证据与诊断、生成与复评、提示词来源、会话接口与存储、工作台六份后，所有 `docs/*.md` 都低于默认上限，棘轮只剩 `AGENTS.md`、`README.md`、`DESIGN.md` 的收紧上限。笔记写法见 [.agents/notes/README.md](../README.md)。
