# 公开仓库保留许可选择与独立 CI 资产准备

日期：2026-10-14
状态：有效
范围：仓库公开设置、公众文档及干净 checkout 的 CI 前置；不改变应用生产行为。

## 背景

维护者要求将仓库改为公开并补齐内容，未指定顶层源码许可证。当前 Git 树包含源码、文档和四张夹具，但忽略模型、个人素材库及运行输出。近期实际 CI 的 API fixture 因缺权重在生命周期启动阶段报错；另一条失败来自当前文档指向未托管的本地素材摘要，开发机器上该文件存在掩盖了交付缺口。

## 决策

公开设置只改变 GitHub 可见性及协作入口，不能推定维护者授予 MIT/Apache 或资产商用许可。公开资料明确源码许可尚未指定、模型和素材另有条款；保留历史证据与提交，不把修改当前说明称为 Git 历史脱敏。

CI 用现有下载器准备并按既有 SHA-256 校验模型，再运行完整 pytest；缓存仅减少重复获取，每次仍校验，不跳过真实 CPU API 回归。前端沿用现有 lint。将可公开的本地摘要文本迁入带日期的版本化证据页，同时保留其原记录缺少实验日期/命令的限制；不纳管原图片。

Wiki 源页面继续与代码同版本。独立 Wiki 的开关、首次网页初始化和 Git 推送分别核对；探测/推送失败不宣称独立页面已发布。

## 被放弃的方案

- 自动加 MIT/Apache：公开请求没有指定许可证，包作者字段也不是授权文件。
- 提交权重或跳过整个 API 套件：前者违背模型资产管理，后者掩盖真实推理前置问题；下载器已存在，无需另建实现。
- 强制纳管忽略目录或加空 README：会混淆运行资产边界或伪造证据。只迁移核实的摘要正文并限定其重放能力。
- 因公开而强推改写历史：本次没有历史重写请求；保留旧结论和实测范围，用新记录说明公开状态。

## 影响与验证

公开后 Git 历史中的实例标识仍可见；扫描仅覆盖明确凭据模式，不保证识别所有秘密。资产下载引入上游网络依赖，缓存命中也不代替摘要校验。独立 Wiki 首次初始化仍是单独的发布前提，源码页面可在此前阅读。
