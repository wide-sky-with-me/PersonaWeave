# 文档可发现性使用入口链接图，检查器保持离线共享

状态：有效
日期：2026-10-14

## 背景

文档、公开协作页与 Wiki 的回归分别维护链接和锚点解析。治理回归用文件名提及判断入链，只检查顶层 docs；孤立页面互链、代码示例或 Changelog 中提到文件名也能通过，不能证明接手者能从当前入口找到它。

## 决策

将纯链接解析归入非生产 [documentation_links.py](../../../scripts/documentation_links.py)，不导入应用、不访问网络或运行数据。当前文档、公共页、Wiki 与笔记复用同一解析，专项回归保留原有发布约束与文件/目录断言。

可发现性从根规则、README、DESIGN、公共协作入口与 Wiki 首页/平台导航沿真实 Markdown 链接遍历，覆盖嵌套验收记录和笔记。Changelog 仍检查链接完整性，但其出链不作为当前导航证据；代码围栏和未被入口连接的互链不算可发现。Wiki 页脚与 PR 模板由平台自动使用，作为明确的导航根，不要求给它们伪造正文入链。

## 被放弃的方案

- 保留文件名搜索：提及和实际链接是不同证据，不能证明阅读路径。
- 给所有文档建立全局手工索引或迁移 docs 子树：增加第二套维护点且影响公开/Wiki 路径，本次没有证明迁移收益。
- 运行应用或在线抓取 GitHub 作为文档检查：会混入实例状态、凭据和网络可用性；本仓库 main/Wiki URL 可映射到版本化源码验证。
- 为机械解析引入完整站点或 Markdown 构建框架：现有文档使用内联链接和 GitHub 标题约定，局部纯函数与反例测试足以覆盖本次边界；参考式链接等新语法须同步扩展检查，不宣称支持全部 Markdown。

## 影响与验证

长度上限、规则/事实/决策分层、旧笔记和实测档案保持原样；历史记录不是当前能力证据。链接与导航反例见 [test_documentation_links.py](../../../tests/test_documentation_links.py)，治理见 [当前文档](../../../docs/documentation-governance.md#机械检查)。本次结构审查范围、回归结果和保留项见 [审查记录](../../../docs/validation/20261014-organization-audit.md)。
