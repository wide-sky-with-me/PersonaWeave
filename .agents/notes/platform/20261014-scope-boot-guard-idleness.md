# 将启动守卫的空闲判断限定为本地推理槽位
状态：有效
日期：2026-10-14

## 背景

提交前只读审查发现：守卫读取健康接口中的 local_inference，在无活动/排队本地任务时重启缺失地址规则的 Colima。跨图聚类和独立身份仲裁在释放本地检测槽位后仍会等待远端 VLM，因而这个快照不能证明所有 HTTP 或付费请求结束。将其描述为全服务无损空闲重启，会把队列指标扩大成未实现的活动请求管理。

## 决策

保留现有守卫实现及原部署不变，但更正交付说明：它只判断本地槽位，自动修复限于运维人员确认没有其他操作的登录恢复窗口；计划运行工程写入或远端仲裁时先停用守卫。交付独立 LaunchAgent 模板、生成/校验/加载/停用步骤，明确安装不会由代码推送自动执行。

本文补充 [地址规则启动顺序决策](20261014-wait-for-tailnet-colima-forwarding.md)的活动判断边界，不取代其关于 Colima 启动快照的故障原因。完整活动请求探测未实现，保留为实际限制，不宣称文档说明已经消除运行风险。

## 被放弃的方案

- 将 local_inference 空闲当成全服务空闲：远端仲裁的等待段不占本地槽位，证据直接反驳这一推断。
- 在提交/文档任务中扩大为跨端点租约和全请求活动管理：会改变并发、状态及取消语义，需要单独设计与回归，不在本次补文档时机械加入。
- 改写既有实测与旧笔记结论：历史记录保留当时范围，由新增说明约束当前交付声明。

## 影响与验证

没有修改或安装生产守卫，也没有改应用模型调用。现有自动周期安装仍须遵守上述使用窗口；不满足时应停用并人工处理转发，不能保证仅靠健康接口避免打断远端请求。
