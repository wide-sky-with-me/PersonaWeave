# 远程识别慢先分离上传与模型耗时

状态：有效
日期：2026-10-14

## 背景

Mac CPU Docker 网页被报告识别极慢。相同摘要的图片在现有容器内检测约 0.1 秒，外部发送托管路径约 1.2 秒，上传完整原图约 19 秒。后台人物库传输也使用同一 Tailscale 链路。客户端 Mihomo 中 Tailscale 控制连接走美国代理，进程名字段为空，进程名规则缺少命中证据。

## 决策

先停止非交互的大量传输，以同图、相同已初始化流水线拆分传图与推理。客户端只保留经连接证据验证的 Tailscale 域名直连例外和既有 Mac 私网接口路由，不改变图像精度、模型 Provider 或生产共享推理并发。

分流必须检查运行中规则及新连接；热加载后旧连接可能保留旧出站。诊断重连只匹配当前 Tailscale 连接，不关闭全部应用连接。配置前保留完整本地备份，报告不复制其中的凭据。

## 被放弃的方案

- 直接增加推理并发或改 GPU：本次模型阶段不构成主要瓶颈，且共享流水线只允许单槽位，未证明并发可用。
- 压缩或缩小原图来掩盖上传慢：可能改变素材质量和小脸结果，本次先保留字节及算法精度。
- 重加单独进程名规则：实测相关连接的进程字段为空，名称匹配缺少命中证据。
- 固化 Mac 公网 UDP 端点或全局 Tailscale 源端口例外：有限试验中均未建立直接连接，临时规则已撤去，不把动态公网地址作为长期配置事实。
- 用 `UDP=true` 或域名规则 `DIRECT` 宣称已建立点对点连接：连接类型须由实际目标 ping/status 验证；本次仍为 DERP(lax)。

## 影响与验证

应用代码、模型和 API 契约未改动。网络调优是本次客户端安装的配置，不作为所有部署的默认值。保留域名分流后的同图重复上传仍有波动；素材库保持暂存而非启用。
