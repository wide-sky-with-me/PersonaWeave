# AI 容器出站复用已验证的宿主代理
状态：有效
日期：2026-10-14

## 背景

用户确认将本项目已有 AI 连接部署到 Mac。六项配置导入后，本地路由就绪，但容器请求所配置上游失败：代理 DNS 为上游域名返回 `198.18.0.6` / `2001:2::6`，容器直连失败。Mac 系统代理及既有 Docker daemon 已使用 7897；通过 Colima 网关同一代理发起只读模型目录请求，两路均鉴权成功且配置模型存在。

## 决策

该实例的应用 `.env` 配置 HTTP_PROXY、HTTPS_PROXY 指向既有 Colima 网关代理；NO_PROXY 保留 localhost、容器回环及应用尾网地址，避免本地 API 健康检查被代理。仅对当前应用容器生效，不更改宿主代理、全局 DNS、模型或用户数据。凭据按用户明确选择，经 SSH 私下迁移六项；模型添加所需 OpenAI 协议前缀，实际模型 ID 保持不变。

## 被放弃的方案

- 只填凭据并以 `ai_refinement_ready=true` 结项：就绪只验证本地配置，不证明出站可达。
- 把当前假 IP 写成 hosts：它属于代理解析结果，不是可直连的上游地址。
- 关闭 TLS 或绕过域名校验：不是本次失败原因。
- 改全局代理或 DNS：会影响该 Mac 的其他应用；已有的出站代理已实际验证。
- 直接访问代理的控制端口：49170 是另一服务入口，CONNECT 返回 404；实际系统及 daemon 代理端口为 7897。

## 影响与验证

应用依赖该 Mac 已有代理的可用性；端口或 Colima 网关变化时须按实例维护，不能把此地址硬编码为所有部署默认值。完整付费精修链路仍须用户显式触发或单独许可验收；只读目录和本地路由初始化不替代真实生成。
