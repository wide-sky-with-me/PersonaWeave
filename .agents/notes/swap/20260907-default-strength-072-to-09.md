# 默认换入强度从 0.72 提到 0.9，不以此绕过遮挡保护

状态：有效
日期：2026-09-07

## 背景

一批四张私人合影的批任务，部分脸没有产生可见变化，被误读成“检测不到人”或“强度不够”。用同一请求、同一素材和映射，仅比较强度 0.72/0.9/0.95 做了一次限定样本诊断（CPU、不调用外部付费模型，脚本 `scripts/diagnose_batch_strength.py`，原任务请求 JSON 的 SHA-256 `0950cbfd6ba47df056c85a2366b5c88eefaeeebf599ac2ca90d6f34274a007a3`）。

## 决策

- 常规默认强度改为 0.9，工作台上限开放到 API 上限 0.95；用户可以退回 0.72，旧请求和原任务不被改写。
- 失败不是没检测到脸：目标匹配分约 1.0，失败来自融合后变化不足。零换脸仍 FAILED、不发布图片，并保留真实检测数、人物结果和模型路由。
- 不以 ArcFace 诊断分强制通过换脸，不为提高指标减弱遮挡、眼镜、密集轮廓或极端侧脸保护。

## 被放弃的方案

- **只靠调高强度解决所有失败**：脸被头发或物体遮挡时 XSeg 掩码均值仅约 0.076，所有档位都应跳过，强行扩大遮罩会产生伪影；侧脸的 0.95 请求强度还要乘 0.65/0.72。
- **把全部衰减归因于强度参数**：72% 下脸框平均实际 alpha 只有 0.217–0.392，保护交集与融合共同削弱可见变化。
- **旧失败记录补写为“检测不到人”或凭空恢复**：只保留当时真实记录。

## 影响与验证

结果（检测脸数/通过脸数 72%→90%→95%）：第 1 张 4/4/4/4；第 2 张 3→2/3/3；第 3 张 2→0/0/1；第 4 张 1→0/0/1。该指标只支持“换入特征增强”，不是自然度评分，也不是身份鉴定；侧脸与眼镜区域仍需人工对照。契约见 [facefusion-local-swap.md](../../../docs/facefusion-local-swap.md)，回归 `tests/test_facefusion_pipeline.py`、`tests/test_strength_contract.py`、`tests/test_task_swap_outcome.py`。后续的 35 脸扫描见 [强度与跳过原因](20261003-identity-strength-and-skip-causes.md)。
