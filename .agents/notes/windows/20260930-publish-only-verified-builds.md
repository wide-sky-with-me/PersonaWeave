# 构建只发布完整且校验过的产物

状态：有效
日期：2026-09-30

## 背景

便携包体积为数 GB 且含个人配置，构建过程中断、复用不可信运行目录、或把私人数据带进公共包都有实际风险。

## 决策

- 在同盘临时目录组装，ZIP 先写临时文件并逐项解压比对清单摘要，全部成功后才与目录、摘要一起发布；失败恢复旧产物，恢复也失败则保留备份并报告位置。
- `--skip-deps` 只复用依赖输入指纹、requirements、runtime 文件集合和逐文件摘要都匹配的成功构建；旧清单没有指纹时必须重装，不给未知旧依赖补写指纹。
- 构建前就拒绝含 `.env`、数据库、`outputs/` 的已使用目录；个人完整包是单独、需授权的叠加步骤。
- 离线分词缓存只接受规范化后匹配既定 SHA-256 的内容，避免离线启动时尝试下载。

## 被放弃的方案

- **直接覆盖正式目录/ZIP**：失败会留下半成品。
- **对任意旧 runtime 补写指纹后复用**：一堆残留文件的摘要不是“安装成功”的证据。
- **不校验 ZIP，只信构建日志**：无法发现打包阶段的损坏。

## 影响与验证

流程见 [windows-portable.md](../../../docs/windows-portable.md)；回归 `tests/test_windows_portable.py`、`tests/test_windows_gpu_upgrade.py`。不承诺多个文件的替换能抵御突然断电。
