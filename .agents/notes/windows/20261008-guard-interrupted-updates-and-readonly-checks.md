# 升级中断须保留启动保护，自检读取不得迁移真实素材库
状态：有效
日期：2026-10-08

## 背景

Linux 回归通过并不能证明 Windows 路径语义成立。原生临时样本确认大小写别名可绕过公共构建的私人数据保护，源码修复包的反斜杠键会与正斜杠清单冲突。修复包直接覆盖正式 ZIP 也会在写入失败时破坏上一版发布。

差分升级逐文件替换；中断后允许同一载荷重试，但进程锁随进程退出释放，启动器缺少混合版本保护。安装自检虽用只读连接枚举素材，随后调用的正式路径解析器却打开写连接、设置 WAL 并迁移表。

## 决策

- 公共构建和升级的私人路径检查归一 Windows 大小写、分隔符；修复清单和 ZIP 成员始终用 POSIX 键。
- 修复包复用正式发布的同盘暂存、成员摘要核验和失败回滚，不另建发布机制。
- 升级通过持久标记保护逐文件替换过程；同一事务恢复后才清除。目标含便携启动器时优先替换它，使旧安装在其他代码变更前获得启动检查。标记只在持锁且完成摘要校验后创建；发布清单后再移除。
- 标记清理本身可能失败。已发布目标清单的恢复分支仍校验替换文件和删除结果，不能仅凭清单一致就解除保护。
- 素材路径解析以 `mode=ro` 打开已有库，保留 containment 校验；数据库建立、迁移仍归写入路径。WAL 查询遵守 SQLite 锁和提交可见性，允许 SQLite 自己维护协调文件，不改变日志模式或业务数据。

## 被放弃的方案

- 每次启动校验全部模型和 runtime：代价大，也掩盖了可直接识别的未完成事务；只检查升级标记，完整摘要自检保留为显式命令。
- 异常时直接删标记：混合文件会被启动，必须保留保护直到恢复完成。
- 只把自检的首次 SQLite 连接改为只读：后续预览归档仍调用写入解析器，未封住真正副作用。
- `immutable=1`：真实素材库可并发更新，不能跳过锁和变化检测来规避 WAL 辅助文件。
- 覆盖正式 ZIP 后才生成校验和：异常会丢失旧发布；沿用已有回滚发布器。
