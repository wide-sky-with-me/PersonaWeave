# Whole-image generation and advisory review

The generation half of a refinement turn. Evidence and diagnosis are in [refinement-analysis.md](refinement-analysis.md), session semantics in [ai-refinement.md](ai-refinement.md), publication in [refinement-session-api.md](refinement-session-api.md). Code: `core/refinement/conversation.py` through `AIGateway`.

## Generation

Before generating, analysis receives the explicitly confirmed diagnosis when supplied, otherwise the full latest completed (`completed` or `review_required`) diagnosis of the exact `base_version_id` as `previous_diagnosis`, separately from bounded prose history. It rechecks those hypotheses against the images and combines supported findings with current human feedback into one plan. Current visual preferences override conflicting earlier suggestions, narrowed scope does not make every issue mandatory, and an unrelated version's diagnosis is never carried over. This is the single analysis call of a generation turn.

`generate(current, people, diagnosis, user_message, model_alias=None) -> (candidate, metadata)` requires an actionable plan and unambiguous person mapping (the core rejects uncertain mapping and no-op diagnoses) and calls `AIGateway.edit_image` **exactly once with one full-resolution lossless current image and text**. The text has the current issues, requested changes, semantic preserve intentions and stable visible person locators. It never attaches the original, reference boards, source photos, face crops, masks, keypoints, annotations or older revisions; analysis therefore turns reference observations into self-contained changes instead of telling the generator to consult absent boards.

Coherent repainting of the whole image is allowed where the intent needs it (lighting, clothing, hair, occlusion boundaries, background). Preserve intentions reduce unrelated drift but are neither a face-only scope gate nor a pixel-equality promise. A single image plus words may not repair a severe identity mismatch, and the references the critic sees are not available to the generator; no identity-recovery guarantee is implied.

Size parameters come only from the declared gateway generation policy via `generation_parameters()` and the shared `image_ops` helpers, never provider-name heuristics. The provider output is decoded and normalized for orientation, color and canvas dimensions (whole-image center-crop/resize only): no landmark realignment, mask, local backfill, `apply_candidate` or acceptance. The normalized result is kept as an immutable candidate **before** review. Metadata records the requested alias, actual model/provider, usage, request ID, prompt version and text, input image count and the normalization audit; the workbench shows provider output and canvas dimensions and states when an enlarged output does not restore detail.

## Advisory review

`review(original, before, candidate, people, references, diagnosis, user_message) -> CandidateReview` sees the original, this turn's before image, the candidate and the same reference boards. `CandidateReview` has `summary`, `improved`, `remaining`, `new_issues`, `uncertainties` and per-person assessments: no score, accept flag or regeneration decision. Prior diagnoses are hypotheses to reassess against visible evidence, a requested non-face change is not automatically a regression, and a clean candidate may have no remaining or new issues. Review never generates, accepts or discards anything; no core method owns filesystem publication or an autonomous loop. A review failure propagates to the turn owner, which keeps the already generated candidate and stores `review_error` for human judgment.

## Errors and retries

Analysis and review each make one structured gateway call, supplying the full JSON schema (including the cross-field consistency rules) up front with `max_text_repairs=0`; invalid output is surfaced instead of repaired by extra text-only calls. Public errors carry only safe classifications (upstream HTTP status when available, timeout, allowlisted schema error codes): provider bodies, model-output values, validation context and extra-field names never appear. This bounds application calls, not network attempts: user-configured LiteLLM Router retries or fallbacks can still cause extra upstream attempts and charges. Other callers, such as identity arbitration, keep their documented default repair budget. Waiting limits are in [ai-refinement.md](ai-refinement.md#waiting-limits). No offline test implies paid service availability or real photo quality.
